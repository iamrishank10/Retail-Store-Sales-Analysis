# Retail Store Sales Analysis using MySQL

**Project Overview**

This project analyzes retail store sales data using MySQL to understand revenue performance, product sales, customer purchasing behavior, and monthly sales trends. It covers basic and advanced SQL concepts, including data manipulation, filtering operators, aggregate functions, table joins, Common Table Expressions (CTEs), and window functions. The project aims to answer business questions, analyze sales performance, identify trends, and generate meaningful insights that can support better business decisions.

**Business Scenario**

You are working as a Business Analyst for a retail store. The store manager wants to understand which products generate the most revenue, how much the store earns, which customers place the most orders, and which product categories perform best.

To achieve this, a database is created in MySQL, sample data is inserted into the tables, and SQL queries are written to answer business questions. The project also explores advanced SQL techniques to perform rankings, compare sales across periods, and calculate running totals.

**Project Objectives**

- Calculate the total revenue generated by the store.
- Find the total number of orders received.
- Identify the products available in the store.
- Find products priced above ₹5,000.
- Analyze revenue generated by each product.
- Identify the highest-revenue product category.
- Analyze the number of orders placed by each customer.
- Identify the city generating the highest revenue.
- Calculate the total quantity of products sold.
- Analyze monthly revenue trends.
- Update existing records and apply filtering conditions using SQL operators.
- Use DISTINCT, GROUP BY, HAVING, ORDER BY, and LIMIT to organize and analyze data.
- Understand primary key, foreign key, and other table constraints.
- Combine related data using INNER, LEFT, RIGHT, and CROSS JOINs.
- Use CTEs to simplify complex queries.
- Apply window functions to rank products, compare results, and analyze sales trends.
- Calculate running totals and compare current-row values with previous or next rows.

**Database Structure**

The project uses three tables:

**1. Customers**

- customer_id — Unique ID for each customer
- customer_name — Name of the customer
- city — Customer's city
- signup_date — Customer registration date

**2. Products**

- product_id — Unique ID for each product
- product_name — Name of the product
- category — Product category
- price — Product price

**3. Orders**

- order_id — Unique ID for each order
- customer_id — Customer who placed the order
- product_id — Product purchased
- order_date — Date of the order
- quantity — Number of units purchased
- total_amount — Total amount for the order

The tables are connected through primary and foreign key relationships to maintain data integrity.

**SQL Concepts Used**

**1. Basic SQL and Data Manipulation**

- Database and table creation
- SELECT and WHERE
- INSERT INTO for adding records
- UPDATE for modifying existing records
- DISTINCT for retrieving unique values
- ALTER TABLE and table constraints

**Primary keys, foreign keys, NOT NULL, and CHECK**

**2. Filtering and Operators**

- Arithmetic operators
- Comparison operators
- Logical operators: AND, OR, and NOT
- IN and NOT IN
- Modulo (%) operator
- Filtering records using multiple conditions

**3. Aggregation and Sorting**

- Aggregate functions: SUM(), COUNT(), AVG(), MIN(), and MAX()
- GROUP BY for grouping records
- HAVING for filtering aggregated results
- ORDER BY for sorting results
- LIMIT for restricting the number of returned rows

**4. Joins**

- INNER JOIN
- LEFT JOIN
- RIGHT JOIN
- CROSS JOIN

**5. Common Table Expressions (CTEs)
**
- Using WITH to create temporary named result sets
- Simplifying complex queries
- Making SQL queries easier to read and organize

**6. Window Functions**

- OVER() and PARTITION BY
- ROW_NUMBER() for assigning row numbers
- RANK() and DENSE_RANK() for ranking results
- LAG() and LEAD() for comparing previous and next rows
- FIRST_VALUE() and LAST_VALUE() for retrieving values from a window
- SUM() OVER() for calculating running totals
- CURRENT ROW for defining the current row in a window frame

**7. Date-Based Analysis**

- Monthly revenue analysis
- Grouping sales by year and month
- Comparing sales across different periods
- Key Business Insights
- Based on the sample dataset used in this project:
- Total Revenue: ₹244,500
- Total Orders: 12
- Total Units Sold: 23
- Top Revenue Category: Electronics, generating ₹200,000
- Top Revenue Products: Laptop and Mobile Phone, generating ₹100,000 each
- Highest-Revenue City: Delhi, generating ₹134,500
- Highest-Revenue Month: January 2025, generating ₹90,000

These findings are based on the sample data created for this project and demonstrate how SQL can be used to analyze retail sales performance. The additional queries extend the project beyond basic reporting to include data manipulation, ranking, comparisons, and running-total calculations.

## Conclusion

This project demonstrates the practical application of SQL in retail sales analysis. It covers database creation and management, data manipulation using UPDATE, filtering with operators, data aggregation, GROUP BY and HAVING clauses, and different types of joins. It also explores advanced SQL concepts such as CTEs, window functions (ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD, FIRST_VALUE, and LAST_VALUE), and running totals using CURRENT ROW. These queries help answer business questions, analyze sales performance, identify trends, and generate meaningful insights from structured retail data.
